# 任务书针对性验证原始记录

本目录记录2026年10月27日在局域网版本上执行的追加测试。数据是临时合成选票，不包含真实学生投票、票码、私钥或保管口令。

- `before-fixes.txt`：在提交0160bb5的程序上运行首批12项新增检查，保留实际失败与异常；对应测试初始版本提交620b69e。
- `regressions.txt`：修复后42项unittest结果，其中15项新增任务书挑战、18项既有联网、9项既有工程回归。边界测试使用1024位密钥缩短运行时间；完整challenge使用2048位。
- `source/challenges.json`：种子2026102707；21轮随机票型、4个定向边界、2个外部JSON示例；同态性质、万人名单与2项安全局限；纯算法10/100/1000票和真实TLS10/100/300票均重复3次，共49项。包含源码文件SHA-256。
- `source/performance.csv`：上述重复测量的均值及联网完整投票阶段最小/最大值。每次原始计时保留在JSON。
- `packaged/challenge/`：最终EXE使用自动生成的新种子重复7轮随机票型及其余快速检查，共19项；记录EXE SHA-256。未重跑EXE的全部大规模性能矩阵，源码数据不会标记为EXE数据。
- `packaged/processes/`：最终EXE的独立服务器、6个独立投票客户端、离线保管端、管理员及查询进程，验证完整投票、重复/关闭拒绝、结果发布和服务重启。预期与实际总票均为[3,2,1]。
- `packaged/ui/`：最终EXE的实际Qt控件流程和截图。两个投票窗口在同一GUI进程，独立进程验证单独保存在processes目录。
- `environment.json`：CPU、内存等测量环境。共享电脑，没有隔离背景负载。
- `verification.json`：最终源码/EXE哈希与证据核对、结果与性能汇总一致性检查。

challenge中的`passed=true`表示检查得到了预期观察；其中`kind=limitation_demonstration`的两项专门复现未防御的风险，不能合并声称“49项攻击防御通过”。单人总票暴露选择也是已说明的边界。所有TLS运行都在127.0.0.1；没有宣称通过两台物理电脑或教师本人现场口试。

代码修复与现场复现说明见`docs/针对性测试记录.md`、`docs/抗AI随机验收.md`。新记录没有覆盖此前单机/联网证据。原报告计时仍对应其历史源码版本。
