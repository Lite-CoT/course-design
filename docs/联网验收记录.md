# 联网版本验收记录

日期：2026年10月27日（北京时间）。此次依据用户指出的课程要求缺口，将默认应用改为通过局域网IP与端口连接的多端投票系统；原单机验收记录只保留为历史。

## 核心要求如何落实

| 要求 | 实现及验证 |
| --- | --- |
| 个人选择不交给服务器 | NetworkClient在本端调用Paillier随机加密；接口只接受密文选票及公开元数据，额外choice字段被拒绝 |
| 服务器不持有解密私钥 | 初始化分离server/trustee/organizer；服务器启动不读保管库，也没有接收私钥或口令的接口；测试检查文件中不含p、q及保管端签名私钥 |
| 服务器能同态统计 | NetworkStore导出时调用aggregate_records，逐选项模n²乘密文，得到各选项总票的密文 |
| 完整总票解密与发布 | 独立离线保管进程核验可信配置、清单、完整集合与乘积后解密签名；服务器和客户端分别验证结果 |
| 多端连接和并发 | 默认Qt客户端填写IP、端口、导入个人凭证；SQLite事务及唯一约束处理并发与重复 |
| 防止名单ID冒用 | 高熵票码在服务器仅保存摘要，绑定ID和角色；知道其他人的ID不等于拥有其凭证 |

此处“服务器”是独立监听HTTPS端口的进程。正式分机使用时只把server目录交给服务器；本机模拟使用独立进程及目录，不能宣称已建立物理隔离。

## 已实际完成的验证

- 18项真实TLS联网测试与9项既有回归，共27项通过。覆盖同ID八次并发仅一次成功、不同ID并发、权限、证书指纹、配置摘要、持久化数据篡改、部分汇总、第二集合解密及伪造结果等。
- 源码和最终Windows EXE分别执行：初始化进程、服务器进程、6个独立投票客户端进程、独立保管解密进程与发布/查询客户端。合成序列[0,1,0,2,0,1]均得到[3,2,1]。
- 两个真实Qt投票窗口通过TLS完成6次控件投票，显示已验证回执及结果；管理员连接使用独立凭证。源码和EXE均完成该流程。
- 关闭后追加及重复投票拒绝；发布后另一个客户端验签读取；停止并重新启动服务后，关闭状态与已发布结果保持一致。
- 网络请求验收在127.0.0.1进行，跨物理电脑的网卡、防火墙和局域网隔离仍需按现场清单验证。

原始JSON、签名汇总包、签名结果、截图、测试输出和源码哈希位于 `evidence/2026-10-27-network/`。合成票的已知明文只存在测试输入记录；不能把这些记录误认为服务器收到明文选择。最终EXE哈希在packaged/network-processes.json中。

## 实际发现并修复的问题

1. SQLite连接上下文会提交/回滚，但不会自动关闭连接，Windows测试目录出现文件占用；初始化和测试使用显式关闭，运行服务的每次事务也明确关闭连接。
2. 冻结程序的管道输出默认编码与测试端UTF-8不一致；统一重定向stdout/stderr为UTF-8后，EXE的独立进程流程通过。
3. 单文件EXE有引导父进程和工作子进程，测试只终止父进程会留下监听进程；测试脚本改为按其自身创建的PID停止整个进程树，避免残留及下一次构建文件占用。

## 文档与剩余边界

三份Word报告沿用原有封面、评分表及页面设置，主体改为联网流程，更新职责、核心代码、截图和实测计时，重新导出并逐页检查。历史10/100/1000人性能数据明确标为原语对照，不作为新的联网千人测试。个人信息和教师签名仍保持待填。

系统主要面对按协议执行但可能试图了解选择的服务器。未实现独热零知识证明、门限解密、独立透明日志、凭证撤销与生产级抗拒绝服务保障。一次批准不能代替首次集合完整性的外部见证，恶意服务器重签删票集合仍需独立回执核对；完整私钥持有者能另行解密单票，小群体总票也可能暴露偏好。上述边界已同步到README、报告与现场清单。
