# 第一题联网架构修正

2026年10月27日，按“客户端输入局域网IP与端口连接投票”的要求修正实现。原单机程序只有本地角色模拟，不能证明服务器在看不到个人选择的条件下接收多端选票；原验收记录对此要求的判断不充分。本文件及后续联网验收记录取代原记录中的整体完成结论。

## 角色与数据流

1. 保管端离线初始化Paillier密钥和投票配置，分别交付服务器运行目录、组织者凭证、保管端目录。只有保管端保存Paillier私钥。
2. 每个桌面客户端输入IP、端口并导入独立投票凭证，核验服务器证书指纹和配置摘要，在客户端把单选编码为独热向量并随机加密。
3. HTTPS接口只接收密文及公开元数据。服务器将凭证绑定名单ID，在SQLite事务内检查关闭状态、防重复并签名登记，不接收明文选择或Paillier私钥。
4. 管理员关闭投票；服务器按选项列对密文相乘，导出完整签名记录与汇总密文。
5. 保管端核验可信配置、签名清单、完整选票集合和汇总，解密总票并签署结果；同一轮次只批准一个确定的汇总。管理员发布签名结果后，所有客户端可读取总票。

## 交付边界

支持局域网多电脑以及本机多进程连接同一端口。认证使用独立高熵投票凭证，组织者负责把凭证交给对应人员；凭证不能替代现实身份核验。TLS证书指纹随凭证分发，避免首次连接到错误服务器。

课程实现仍不提供密文独热零知识证明、门限解密、公开透明日志或生产级抗拒绝服务保障。完整私钥持有者能另行解密单票；小群体总票本身可能揭示偏好。服务器隔离、网络请求、事务并发和错误路径须以新增联网测试验证，不能沿用原单机测试冒充多端验收。
