# 第一题现场验收步骤

本清单是待执行的操作说明，不能视为已通过教师现场验收。使用临时目录和虚拟 ID；由验收人员临时指定人数、选项和选择序列。

## 1. 准备

按 README 启动源码或本机构建的 `dist/MiPiaoLab.exe`。创建一个新的临时投票目录，使用至少 8 字符的保管口令。演示结束后保留结果 CSV、公开包及必要截图；完整投票目录含私钥保管库，不提交到 Git。

## 2. 随机数据与同态流程

1. 在“创建与管理”输入临时题目、逗号分隔选项和名单人数。支持 2–8 个选项、1–10000 个名单 ID；每张票在多个选项中单选一个。
2. 点击“选择目录并创建”。由验收人员现场指定若干 ID 的选择；旁边纸面记录每个选项的预期计数。
3. 在“加密投票”逐票提交，查看公开选票中的轮次、ID、票型、时间、nonce 和密文向量；说明公开 nonce 不是 Paillier 内部随机数 r。相同选择的两张票通常具有不同密文。
4. 在关闭前请求计票，应被拒绝。点击“关闭本轮投票”后，再次提交新票也应被拒绝。
5. 在“汇总与结果”点击“审计并解密总票数”，输入正确口令。核对每个选项结果与纸面计数、总和与接收票数一致。记录界面实际显示的审计、汇总及解密耗时。
6. 导出结果 CSV。再创建不同人数、不同选项数量的新轮次重复操作；旧轮次不能直接改变维度继续投票。

需要演示无私钥计票时，导出“无私钥公开包”，解压到新的目录。确认该目录没有 `private/`，在仓库根目录打开 PowerShell，用以下命令对解压后的根目录汇总：

```powershell
$env:PYTHONPATH = (Resolve-Path src).Path
.\.venv\Scripts\python.exe -c "from tally_service import aggregate; from pprint import pprint; pprint(aggregate(r'替换为解压根目录的绝对路径'))"
```

输出是汇总密文与摘要，不是总票明文。解释列乘积为何等于明文计数之和；保管端会独立复算完整请求，才使用私钥解密。

## 3. 拒绝与审计

| 操作 | 预期现象 | 现场结果/截图 |
| --- | --- | --- |
| 同一个有效 ID 重复投票 | 拒绝，接收票数不增加 | 待填写 |
| 输入名单外 ID | 拒绝，不产生有效选票 | 待填写 |
| 输入错误保管口令 | 拒绝解密，不显示新结果 | 待填写 |
| 审计页“演示篡改检测” | 临时副本被识别为异常，原数据仍能审计 | 待填写 |
| 审计页“演示删除检测” | 临时副本被识别为异常，原数据仍能审计 | 待填写 |
| 重启，打开已关闭轮次 | 持久化数据可读，仍不能追加投票 | 待填写 |
| 改变选项数量并创建新轮次 | 新维度正常计票，不混用旧票 | 待填写 |

演示按钮使用副本。若教师要求亲自删除或修改文件，先将演示投票完整复制到新的临时目录，关闭对原目录的操作，再对副本进行修改并审计。文件同步不完整和意外损坏也会触发完整性告警，因此告警不能单独证明有人恶意攻击。

## 4. 失败边界与现场小改

- A 解释独热编码与随机加密，并现场调整一个合法输入或错误提示；说明客户端生成 0/1 不等于可验证每张密文都是 0/1。
- B 解释汇总单位元 1、零票结果、模 n 回绕上限和完整请求校验；演示拒绝单票请求。单人总票会暴露选择，完整私钥持有者仍能另写代码解密单票。
- C 解释签名清单怎样发现删除/篡改，以及为何整套旧签名状态回滚仍能通过；说明名单 ID、公开配置和本地文件锁各自的作用。

小改题目以教师现场要求为准。修改后先运行相关回归，再说明对其他模块的影响并提交本人实际修改。不要为了“全部通过”删除拒绝条件或隐藏已知局限。
