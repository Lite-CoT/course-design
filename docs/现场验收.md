# 局域网多端现场验收

本清单为现场执行说明。自动测试已验证本机真实TLS与多进程；跨物理电脑、教师随机数据、口试和现场小改须另行记录。

## 一、准备三类角色

按README初始化新轮次。只将server目录部署到服务器电脑；保管者持有trustee目录及口令，管理员持有admin.ticket.json，各投票人各自持有一份Vxxxx.ticket.json。查看server目录没有trustee.vault；服务器的TLS/登记签名私钥不等于Paillier解密私钥。

启动serve，指定监听IP和端口。服务器运行ipconfig确认局域网IPv4地址；客户端填写该地址与端口。本机多端填写127.0.0.1。记录实际IP、端口、网络环境和防火墙情况，不将尚未测过的跨机连接填写为通过。

## 二、临时指定输入并投票

1. 由验收人员指定2–8个选项和名单人数，重新初始化新轮次。人数可配置1–10000，本轮性能实测不代表全部规模均已验证。
2. 打开两个或更多客户端，导入不同凭证连接同一服务器；记录各端ID和纸面预期计数。
3. 每个客户端选择并提交，界面验证回执签名与密文摘要。说明选项索引只在客户端加密前使用，网络投票对象仅含公开元数据与密文。
4. 同时使用同一ID投票，服务器应只登记一次。以另一个投票人的ID构造请求，应因票码绑定不符而拒绝。
5. 在开放状态尝试导出汇总，应被拒绝；普通投票人不能关闭投票或发布结果。

## 三、无私钥服务器完成密文统计

管理员关闭投票，导出密文汇总。该文件包含公钥配置、签名清单、密文选票及列乘积，不含私钥或明文选择。对照源代码说明服务器的C_j=∏c_ij mod n²，不执行raw_decrypt。

将文件交给保管者，运行README中的decrypt命令并在保管电脑输入口令。保管端核验可信配置和完整乘积，输出签名总票。管理员发布，各端刷新，核对每项计数及总和与纸面记录一致。

服务器只获取签名后的总票。保管者若仍在同一电脑运行，这是同机多角色测试；实际物理隔离需要分别部署，不能只靠目录名称证明。

## 四、失败与恢复

| 操作 | 预期 | 现场记录 |
| --- | --- | --- |
| 错误票码、冒用ID | 401或403拒绝，接收票数不增加 | 待填写 |
| 错误证书指纹 | 发送票码/选票之前停止连接 | 待填写 |
| 重复ID并发提交 | 仅一次成功，其余409冲突 | 待填写 |
| 关闭后追加 | 拒绝，清单不变 | 待填写 |
| 修改/删除数据库选票记录 | 与签名清单不一致，拒绝正常审计/汇总 | 待填写 |
| 修改导出的汇总密文或只保留部分请求 | 保管端复核失败，不解密发布 | 待填写 |
| 伪造或修改结果签名 | 服务器拒绝发布，客户端也不接受 | 待填写 |
| 已批准后换另一个合法签名集合 | 保管端拒绝批准第二个不同集合 | 待填写 |
| 提交后连接中断 | 重新连接查询本人回执，不盲目当成未投 | 待填写 |
| 重启服务器 | 接收记录、关闭状态、已发布结果保留 | 待填写 |

破坏性演示只在单独的合成测试副本上操作。文件损坏、误操作或同步不完整也可能造成完整性告警，不能仅凭告警断言发生恶意攻击。
